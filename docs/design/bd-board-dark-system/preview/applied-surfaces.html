Preview 09 · Applied UI

The four source screens, live

Each frame below loads the preserved source file directly, unmodified. This is the ground truth the rest of the package was measured against — if a token here disagrees with a token in colors_and_type.css, the screen is right.

../board.html · ../bead-detail.html · ../projects.html · ../knowledge-detail.html
01 · Board — shell, swimlanes, filter bar

Try it: press / to focus search, switch Group by between Epics, Priority and Status, collapse a lane, or open the Knowledge tab. All of it persists to localStorage under bdb.board.v1.

02 · Bead detail — the shared sheet

Press Delete to see the destructive pattern: the dialog names the exact edge loss, previews the CLI command, and keeps the confirm button disabled until you type the bead id character for character.

03 · Projects — the dashboard surface

The only screen with charts. Both encodings are filled, both are labelled, and the stat tile footnote always gives the share of the total so a raw count never has to carry the meaning alone.

04 · Knowledge detail — the same sheet, a second object

Reusing the sheet is the design decision. A knowledge entry is only a bead comment with a recognised prefix, but giving it the same object-detail surface as a bead is what makes it feel like a thing you can navigate to, cite and share.

00 · The author's rationale page

This page is the source of the contrast numbers quoted throughout the package — 5.15:1, 6.59:1, the 4.34:1 failure it replaced, and the four decisions that shaped the system. It is written in Portuguese because it is design rationale, not product surface; that split is documented in DESIGN.md §9.
