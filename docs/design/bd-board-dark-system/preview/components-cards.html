Cards, rows and data marks

Rendered from the preserved source stylesheet and the preserved sample dataset — these are the real bead cards, not redrawn approximations. The dataset mirrors bd-board's own roadmap, which is why the titles read like work instead of lorem.

assets/bd-dark.css + assets/board-data.js — both preserved, loaded live
Bead card — the atom of the board

Three rows, always in this order: id · priority · state tag · age, then a 2-line clamped title, then labels and a mono stat cluster — subtasks, blocked-by (red), blocking, related, comments, assignee monogram. An epic adds a 2px --primary-text left border and a stacked progress bar over its children.

Lane cell — a column inside a swimlane
—

A lane cell is a recessed --canvas well at 10px radius with a 5% ring, so cards read as sitting in a column rather than floating on the page. Empty cells show an em dash at 22% white, never a blank box.

Knowledge row — hue stripe, chip, excerpt, source

The stripe and the chip both derive from the entry's single hue token via color-mix. Hovering tints the ring with that hue — not with the accent, because the accent means "the app", and this colour means "this kind of knowledge".

Dashboard marks — stat tile and project card

The stat tile's value takes the status colour, and the mono footnote always states the share of the whole, so a large number never reads as significant on its own. The project card pairs a stacked bar with a completion ring: the same data twice, once as composition and once as a single number.
